CABLEMAP / REFERENCE MAP

Follow one connection.

CableMap checks an authored AV signal model, keeps the reviewed graph in the browser, and prints the same accepted cables. This is a reference route; no learner walkthrough or personal learning outcome is claimed.

1 / USER INPUT

Select two ports

src/app.ts → connect() reads the selected endpoints. It does not add a cable before validation succeeds.

2 / EXPLAIN THE RESULT

Check the declared path

src/validation.ts → validateConnection() rejects direction, signal, occupation and unknown endpoints. analyzeGraph() follows cables and internal routes to each sink.

3 / SAME GRAPH, TWO OUTPUTS

Review and print

src/app.ts → render() shows the accepted graph or separate rejected preview. src/print.ts → patchRows() derives the exact accepted cable list.

To change this, start here

  • Declared device ports and conversions: catalog.ts, CATALOG.
  • What survives a reload: storage.ts, loadProject() and saveProject(). Saving is explicit; failed loads do not overwrite the snapshot.
  • Layout, print styling and focus outlines: public/styles.css.
  • Observable regression evidence: domain tests and browser workflow.

A practice to reuse

A compatible cable does not prove a complete signal path. The upstream-disconnect test removes the laptop’s USB cable while preserving downstream cables; the speaker must become unresolved. Turning that distinction into an observable acceptance criterion prevents a plausible diagram from becoming a false success claim.
